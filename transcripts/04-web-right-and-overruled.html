To contact one, use the `a2a_send_message` tool: it delivers your `content` to the named agent and, by default, waits for that agent's reply and returns it — messages from other agents that arrive in the meantime are held for you. To write to several agents before reading any reply, pass `wait_for_reply: false`; the call then returns as soon as the message is handed to the service, and `a2a_wait_for_messages` collects whatever has arrived (optionally from one named agent). The agent you write to sees only the `content` you send and nothing else (not this workspace or its files), so make each message self-contained.

A message that arrives for you opens with an `[a2a message]` header carrying the message's protocol fields: `from:` is the sending agent, listed under that same name in `a2a_list_agents`, so it is the name to use as `to` when you answer; `role:` is the sender's A2A role; `messageId`, `contextId` and `taskId` identify the message and the work it belongs to. Everything after the blank line is the agent's own text.

Reply by calling `a2a_send_message` back to that agent: one message in, one message out. Your written output is for whoever assigned you the work; it reaches no agent, so nothing you leave there is delivered.
